\section{Linear Baseline}
\label{sec:linear_baseline}

\subsection{Method}

As a reference point for all other models, we fit linear regression on the
3 operating settings and 21 raw sensor readings of the current cycle (24
features). Each feature is standardised (zero mean, unit variance) using
statistics from the 80 training engines only. We compare ordinary least
squares (OLS) with two regularised variants:
\begin{itemize}
  \item \textbf{Ridge}, which adds an L2 penalty $\alpha \sum_j \beta_j^2$;
  \item \textbf{Elastic Net}, which mixes L1 and L2 penalties and can set
        coefficients exactly to zero.
\end{itemize}
The search grids were kept small to avoid overfitting the single validation
split: $\alpha \in \{0.01, 0.1, 1, 10, 100, 1000\}$ for Ridge, and
$\alpha \in \{0.001, 0.01, 0.1, 1\}$ with L1 ratio $\in \{0.2, 0.5, 0.8\}$ for
Elastic Net. Settings were chosen by validation RMSE
(Section~\ref{sec:evaluation}).

\subsection{Results}

Table~\ref{tab:linear_baseline} lists the best setting of each model family.
All three reach a validation RMSE of 42.92 cycles. OLS was kept as the
simplest model and scored once on the test set: MAE 24.91 and RMSE 31.17
cycles.

\textbf{Regularisation gives no measurable gain.} On all rows, the training
RMSE of OLS (43.31 cycles) is close to its validation RMSE (49.72 cycles). The
model is therefore underfitting (high bias) rather than overfitting (high
variance). Regularisation reduces variance, so with 16{,}390 training rows
for 24 features it has nothing to correct. Stronger penalties changed the
validation RMSE by at most about 0.6 cycles, which is within the noise of 20
validation engines.

\textbf{Uninformative and correlated inputs.} Seven features are constant
across the training engines (\texttt{setting\_3}, \texttt{sensor\_1},
\texttt{sensor\_5}, \texttt{sensor\_10}, \texttt{sensor\_16},
\texttt{sensor\_18} and \texttt{sensor\_19}), so they receive near-zero
coefficients in every model. Seven feature pairs have absolute Pearson
correlation of at least 0.8, the strongest being \texttt{sensor\_9} and
\texttt{sensor\_14} at 0.96. Individual coefficients should therefore not be
read as the effect of one sensor.

\textbf{Where the linear model fails.} Predictions level off at about 150
cycles (Fig.~\ref{fig:linear_diagnostics}). Engines with true RUL between 200
and 330 cycles are all predicted at roughly 120--160, and mid-range engines
tend to be over-predicted. The residual Q-Q plot shows a heavy right tail from
these large-RUL misses. Fig.~\ref{fig:top_sensor} shows the likely reason:
\texttt{sensor\_11}, the input with the largest coefficient, is flat and noisy
until RUL falls below about 150 cycles and changes only near failure. A single
current-cycle reading cannot separate RUL 200 from RUL 300. In addition, 4 of
the 100 validation predictions are negative, which is physically impossible;
they were left unclipped, because clipping would change the model.

\textbf{Validation versus test.} The test RMSE (31.17) is lower than the
validation RMSE (42.92). A plausible but unconfirmed explanation is that the
validation cut-offs include very large RUL values that this model misses. We
did not examine the test RUL distribution, since the protocol forbids it.

These results suggest two next steps:
\begin{itemize}
  \item trend features such as rolling means and slopes, which add the
        information a single reading lacks;
  \item more flexible models, such as trees and sequence models.
\end{itemize}
